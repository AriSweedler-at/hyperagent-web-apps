# CSS <-> TS class contract

Every class a game's TypeScript names has a rule in the stylesheet its page links, and every class
that stylesheet styles is named by TypeScript or carried by the page markup.
`test/dist/class-contract.test.ts` (docs/MIGRATION.md step 14; from `npm run test:site`, after the
build) enforces both directions on dist/ for each game, reading three sources through
`test/dist/classes.ts`:

- TS-named: the quoted names passed to `toggleClass`/`addClass`/`removeClass`/`hasClass`
  (`web/shared/edge/dom.ts`), the fidice vdom's `class:` props and the quoted arguments of its
  `cls(...)`, and the words of every `class="..."` attribute in a template string (plus the quoted
  words of a `${...}` ternary inside it), over `web/games/<g>/**` and `web/shared/**` (`.ts`, not
  tests).
- Markup: the `class="..."` attributes of the served `games/<g>/index.html` (for a shell game the
  file `tools/shell-markup.ts` composes from `web/shared/markup/shell/*.html` and the game's
  `page.ts`, docs/design/dry-round-2.md G2; the committed, served bytes are what is read).
- CSS: every `.name` in the stylesheets the page links (the shared chunk's
  `dist/shared/assets/<chunk>-<hash>.css`, which is `web/shared/styles/{tokens,base}.css`; on a
  shell page the shell games' sheet, `web/shared/styles/shell.css` (docs/design/dry-round-2.md G1),
  which fidice never links before its restyle; then `dist/shared/assets/<g>-<hash>.css`, its
  theme), with comments and strings blanked first.

The extraction is a few documented regular expressions, not a parser. Everything it cannot see is a
row below, and the test checks each row against the tree so a row cannot go stale (a class whose
rule is gone, a "dead" rule TS started naming). Adding a screen or a class means keeping this table
true (docs/ARCHITECTURE.md "Conventions for small diffs"); a class named literally and styled needs
no row.

Rules of the table:

- `Owner` is `gin-rummy`, `fidice`, `backgammon`, `shared` (a `shared` row applies to every game) or
  `shell` (the pages with the shared shell, `tools/games.ts` `SHELL_GAMES`: gin-rummy, backgammon and briscola;
  a `shared` row is checked against fidice's stylesheet too, so a class fidice does not style cannot
  be one until the Fidice restyle; docs/design/dry-round-2.md G3).
- `Kind` is `class`; `id` and `attr` rows are not checked yet.
- `Name` is one class or several separated by spaces (`m0 m1 m2 m3 m4`).
- `Toggled by` names the TS module that produces the name; `Styled in` the stylesheet with the rule.
- Both filled: TS builds the name in a way the extraction cannot see, and the rule must exist.
- `Styled in` empty: a behaviour-only hook (no rule may exist for it, or the row is stale).
- `Toggled by` empty: markup-only or dead CSS (nothing in TS may name it, or the row is stale).

restyles Fidice to look like Gin, so `web/shared/styles/tokens.css` declares the thirteen palette

### Shell tokens

The shell's roles (`web/shared/styles/shell.css`, docs/design/dry-round-2.md G1): where the two shell
themes gave one shell rule two values that differ by palette, radius or face, the rule reads one of
these fourteen names. `tokens.css` declares them with gin's values (gin's `theme.css` declares
none), backgammon's `theme.css` redeclares every one on its `:root`, and fidice, which links no
`shell.css`, declares none (its column is empty until the restyle, G5, decides). `test/tokens.test.ts`
pins the three, and that `shell.css` reads every one and declares nothing. What the two themes
still spell under a shell selector is the type scale (font sizes and weights, letter-spacing, a
padding or margin; one scale is G5's) and what one theme alone has (gin's `.card-box` hairline
and gold `.sheet` border, the toast's cream; backgammon's `font-family: inherit` on every control,
its panel shadows and gold underline, `cursor: pointer`). A role one rule alone needs (the
`.overlay` scrim, the toast's fill and label, the sheet's radius, the submenu's and the toast's
shadows) stays a per-theme declaration under that selector rather than a token.
