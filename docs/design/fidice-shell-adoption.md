# Fidice on the shared shell: the adoption plan

Fidice keeps its look (palette, type scale, dice art) and loses its own shell, net model and view
helpers to the shared shell (`reduceShell` + `ShellConfig` + `bootShell`, docs/design/shared-shell.md)
and the shared N-seat sessions (docs/design/n-seat-sessions.md, landed as #143). Anchors are
`main` @ e99e223 (#143 merged; `origin/briscola-online-seats` is gone, so "N-seat as PR-5 lands it"
means `main`: `cfg.seats` web/shared/ui/shell.ts:698, `opts.capacity` :708, `net.seats`
web/shared/edge/boot.ts:405, `HostOptions.capacity/waiting/names` web/shared/net/host.ts:202-220).
Plan only: the first PR opens after briscola is complete (the owner's sequencing). This document
supersedes shared-shell.md §4.6 ("not by adopting this shell"); M6 rewrites that section as landed.

## 1. The ask and the answer

The owner, 2026-09-25, verbatim: "I don't want it to look like gin rummy (no style no palette). But
I DO want the full shell adoption. That can and should be deferred until AFTER briscola is complete,
though. We have a lot less users and interest and revenue generated from fidice, so it's not a
priority. But I also don't wanna have to support its tech debt".

1. The look is tokens: `theme.css:8-23` already redeclares the 13 palette names; it gains the 14
   shell roles on its own values (backgammon `theme.css:17-50` is the pattern) and the page links the
   token-only `shell.css` (:1-20). No fidice rule ever resolves to a gin value (§5).
2. Home, waiting rooms, rules, result, history, curtain, toast, save/resume and boot become the
   shared shell's, through a fidice `page.ts`, `shellConfig.ts` and `ui/state.ts`: briscola's shape.
3. Net moves onto the shared N-seat sessions as landed: `seats {min: 1, max: 6}`, `capacity` from
   the host card, `renameGuest`, seat lists, rejoin by name. No shared shell code changes; the one shared edit is the
   `SHELL_GAMES` list (`web/shared/ui/ids.ts:11`).
4. The engine never moves: `domain/**`, `bots/**`, `net/protocol.ts`'s decoders and `legacy/` are
   untouched, so `test/parity/fidice.legacy.test.ts` (12 seeded bot games) and `fidice.modules.test.ts`
   are green at every merge. That is the gate for "every fidice rule and bot behaviour still passes".
5. Mechanism: the shell path is built dark beside the live app behind `?shell=1` (one page, two
   boots), proven by the eight shell specs, its own spec, a replay oracle and a soak, then flipped
   once and the old code deleted once (M6). The screen-by-screen cut-over was scored and lost (§4).
6. The live page changes three times before the flip: a CSS link proven 0-value-diff, page bytes the
   vdom wipes, a flag read. Everything else lands as new files nothing imports.
7. The view and sessions oracles guard the live path untouched until M6, where they split/retire with
   their subject and a sentence why; the new path has the replay oracle from M3.
8. After the flip the table, spectator, ladder and config paint through the DOM edge (M7): the vdom,
   `uiOf` and the view helpers go. That is "done".
9. Twelve merges (fifteen with splits), one HIGH PR (M7) behind every e2e; about +7,000/-9,000 lines;
   the `web/shared/**` code diff is `web/shared/ui/ids.ts:11`; the rest under it is comments
   and CONTRACT.md rows that say "until the restyle".
10. Thirteen decisions (§7) have v1 defaults; five shape e2e words and are final at M5; all are final at
    the flip gate; each is a one-file change while dark.

## 4. The plan: small PRs, each behaviour-preserving, merged on green

Two plans were scored on seven criteria (behaviour preserved at every merge, look kept, diff size,
oracle protection, time to "old code gone", risk to the live page, fit with the N-seat shell): A cut
the live page over one screen at a time through a ~150-line bridge (three HIGH PRs, one oracle
restructure, one golden flip per screen) and scored 20; B builds the shell path dark beside the live
app and flips once, and scored 30. The plan below is B's spine with seven grafts from A (tokens
first, the waiting-room bot controls, the table rewrite as a required tail, A's decisions as v1
defaults, the history/sound/six-seat/docs PRs, the `retired` manifest mark, the fuller `page.ts`).

Rules every PR obeys: code moves, it is not rewritten; `domain/**`, `bots/**`, `net/protocol.ts`'s
decoders and `legacy/` never change; every PR runs typecheck, lint, `test:fidice --coverage`,
`test:shared`, `test:harness`, build, `test:site`, the goldens `--check`, and e2e where a spec names
fidice; the body carries `git diff --stat origin/main -- web/shared tools/games.ts` (expected code
change: `ids.ts:11` at M5; comments and CONTRACT.md rows otherwise); a new folder registers its
coverage row, `tsconfig.node.json` include and CONTRACT.md rows in the PR that creates it; main is unprotected, so watch CI and merge, never `--auto`.
The mechanism the plan rests on: `mount` = `patchChildren(root, [tree])` (src/view/vdom.ts:182-185)
replaces `#app`'s children, so composed shell screens inside `#app` never show on the old path; the
Worker keeps `url.search` (infra/games-proxy/worker.ts:184, 187), so `games.sweedler.com/fidice/?shell=1`
reaches the page for the soak; `bootShell` reads `win.__rng` (boot.ts:463) as the old boot does.
