## 1. The ask and the answer

The ask, verbatim: "I would like the hyperagent-web-apps to get moved to the 'games' repo, eventually. But a BUNCH of stuff has to happen for this to be possible. So ultracode to plan this (all commits are ari@sweedler.com, move the repo to a newly created personal gh repo, change cloudflare stuff). Don't implement this, just plan it and remember for later"

The answer:

1. Cloudflare is already personal: both Workers (`hyperagent-web-apps-games`, `hyperagent-web-apps-turn`) and the sweedler.com zone live in the "Sweedler Family" account 703785c2d2a7bdc97432fa2833a2397d. "Change cloudflare stuff" is two `wrangler deploy` runs by Ari (a new upstream, a widened CORS list), not an account move; no DNS or TLS changes at all.
2. The site has no origin baked in: vite `base: './'` (vite.config.ts:44), the invite link is `${location.origin}${location.pathname}`, peer ids are origin-free. The rewritten repo's dist serves at `https://arisweedler.github.io/games/` on its first CI run with no code change.
3. The advertised URL, games.sweedler.com, is byte-identical before and after: the Worker keeps its name and custom domain and only its upstream constants change (infra/games-proxy/worker.ts:22,24). Every invite link, bookmark and localStorage save on that origin survives.
4. Ownership-bearing literals are few: e2e/fixtures/site.ts:27,53, worker.ts:22,24,47 (+44 test rows), eslint.config.js:90, infra/turn-worker/wrangler.toml:11, web/index.html:43, package.json:35, plus prose. Three PRs, landed in the OLD repo first so the carried tree is already origin-agnostic.
5. History: `git filter-repo --mailmap` over a bare clone maps three identities (author `ari.sweedler@airtable.com` and `ari@airtable.com`; committer `GitHub <noreply@github.com>` on every squash merge) to `Ari Sweedler <ari@sweedler.com>` on author and committer. Trees are unchanged (tree hash checked); all 92 signatures are lost; every SHA changes.
6. The new repo is created empty with the PERSONAL token, receives the rewritten `main` as its first push, gets Pages `build_type=workflow` by one API call, and needs no secret: the deploy job is OIDC and repo-agnostic (.github/workflows/ci.yml:355-390).
7. The flip is one Worker deploy after a 1-3 day parallel window in which both Pages origins are live; rollback is `wrangler rollback` for as long as the old Pages serves the real site.
8. The old repo is archived with a "Moved to" description after a final `workflow_dispatch` deploy of redirect stubs to its Pages, so old Pages URLs forward (query and hash intact) to games.sweedler.com. It keeps the 91 PR autolinks, 298 KB of PR-body design records and issue #19.
9. Locally: the checkout keeps its path (the assistant memory dir is keyed by it), gets `git remote set-url origin` + `git config --local user.email ari@sweedler.com` (the includeIf at ~/.gitconfig:69 otherwise imposes the work identity on every repo under $HOME), and every `gh` call pins `--user AriSweedler`.
10. Effort: 8 required PRs (PR-docs, PR-1, PR-2, PR-3, PR-0, PR-4, PR-6 and the pre-push hook PR of 5.8 step 2; +1 optional flatten), 12-14 agent hours, about 2 Ari hours (three `wrangler deploy` runs, one token-bearing push watched, a few dashboard reads), spread over 2-3 weeks for the parallel run and soak. Approaches B and C are recorded as later hosting projects, not part of the move.
